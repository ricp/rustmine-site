Current status · reviewed 21 November 2026 UTC

What RustMine can claim today.

RustMine is Richard Piacentini’s independent experiment to rebuild Redmine’s core in Rust while preserving the data and behavior people rely on. It is still in development. It is not a completed Alpha, a released demo or a production replacement for Redmine.

Availability and source

The application source remains private. There is no publicly released RustMine installer, container or hosted hands-on demo established by the current evidence. The public website repository contains this informational site, not the application source. Existing screenshots and recordings show dated development work, not access to a current service.

Plugin compatibility is deferred. RustMine is not ready for customer installations. There is no measured performance or hosting-cost advantage to report, and no completion percentage or release date is promised.

Verified local work · 21 November UTC

Issue moves, bulk edits and hours filters pass focused checks. The 20 November, 18:52 UTC checkpoint verified moving an issue and its children with attachment bytes and history preserved, separate bulk assignee clear and restore, notes on the changed issue without a note on its unchanged ancestor, tracker defaults/history and selected hours filters.

Separate Chrome checks verified as of 21 November cover clearing a parent and reattaching it through autocomplete. A selected move with a public note in one save preserved four attachments and moved a logged hour. The later focused test-only checkpoint is not newer deployed application behavior.

These are selected local workflows, not full compatibility, a released demo or an installable Alpha. During Alpha, we plan to check the rollout using safe copies of existing Redmine data and files. Read the evidence and limits; read the dated journal entry.

What has actually been checked

  • Project forms: five designed browser scenarios were functionally accepted on 6 November 2026 against Redmine 7.0.3, using separate copies of the same fixture database and files: successful creation, missing name, duplicate identifier, permission denial and editing. Timestamp, UI and partial request-capture qualifications remain. This is not acceptance of every project workflow.
  • Local SQLite workflows: focused Rust Router tests and selected controlled HTTP checks cover slices of issue queries, custom fields, grouping, totals, saved queries, time entries and CSV, LDAP administration, signup, preferences and account changes. The November 18 work includes targeted account-token revocation, encrypted notification intents and rollback under injected native outbox faults. Many checks use synthetic fixtures and selected test entry points. Their counts are not global compatibility scores.
  • Redmine baselines: source comparisons use pinned Redmine 7.0.2 references; the separate five-case project-form comparison used 7.0.3. Neither baseline implies compatibility with every release, configuration or extension.
  • PostgreSQL preparation: dated 1 November local Mac ARM64 work used PostgreSQL 18.6 and schema derived from Redmine 7.0.2 migrations, with synthetic demo rows and bounded login, restart, logout and preservation checks. Hosted AMD64/PostgreSQL demo acceptance is still unverified. Later SQLite checks do not upgrade that older preparation.

The current review is dated 21 November UTC; the focused issue-workflow results are summarized above. The earlier 18 November review included local notification-message checks, while the 18 November progress summary retains its own 05:50 UTC source cutoff and limits. These evidence dates do not mean the application was deployed.

What remains unverified or unsupported

  • Full Redmine feature, permission, plugin, localization, wire-format and whole-page parity; complete browser journeys; production, security and concurrency certification.
  • General PostgreSQL/MySQL runtime parity. Positive timestamp grouping, SQL/decoder/session-timezone behavior and broader hosted database gates remain separate. SQLite Closed-date grouping remains flat; the grouped-spent provider intersection is still held.
  • Known bounded limitations remain, including Tracker NULL-reference hydration, Priority type/mask cases and non-atomic count/SUM reads. CSV checks do not establish every encoding, field format or pagination combination.
  • Real-directory and LDAPS certification. Controlled LDAP bind/search/login and administrator-form checks are not a generic directory guarantee.
  • Complete theme acceptance. Default/core is selected but broader visual/interaction acceptance remains open. Classic and Alternate are separately implemented and package checked, with visual review and accepted-preview integration pending. Foundry, Clearline and Common Ground are each experimental and unintegrated.

Some areas are implemented on a branch, others have passed focused validation, and only explicitly dated work is integrated into a review preview. Source review, a successful build, a corrected fixture or a later passing run does not prove an earlier failed execution restored its data.

How to assess the evidence
